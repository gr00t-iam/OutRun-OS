3. WHAT CHANGED IN 1.0 (since the v0.96-dev desktop milestone)
--------------------------------------------------------------

  apps/calc.c        Operator precedence: * and / bind tighter than + and -,
                     equal precedence left-to-right. Two-level pending stack
                     (lhs/op + low_lhs/low_op) — with two levels there is never
                     a third, so it is a complete stack. Deferred operations are
                     overflow/zero-divide checked when finally applied. The
                     "Pending:" line shows both operators ("+ *").
  apps/vault_pad.c   g/G document jumps. One-line clipboard: y yank, D cut,
                     p paste-below (1 KiB cap; an over-long line is REFUSED, not
                     truncated). Overwrite confirmation: save onto a file that
                     exists and is not this buffer's origin asks once; the next
                     save confirms; any other key withdraws. The existence probe
                     opens with flags 0 so it cannot create.
  apps/task_mgr.c    Click PID / CPU column headers to sort. Stable insertion
                     sort producing an index table over the kernel's list — the
                     list itself is never permuted, so monitor_sample's cross-
                     sample pid matching is untouched (asserted). Per-row CPU
                     share column. NO memory sort: outrun_process has no memory
                     field and a fabricated column is not a feature. Graphs
                     auto-scale to the observed peak with a floor of 20.
  apps/settings.c    Instant apply: a row click pushes to the kernel in the
                     same step; on refusal the local copy rolls back so the
                     screen never shows a value the desktop is not honouring.
                     APPLY button removed; RELOAD kept.
  kernel64.c         Desktop heartbeat prints frames_used= by the same
                     expression SYS_DESKTOP_INFO reports (needed so the soak
                     reads a counter something actually prints).
                     KERNEL_VERSION 1.0.0-metal.
  Makefile           VERSION 1.0.0. New: desktop-soak, gate-desktop.
                     release-iso builds + checksums BOTH images; release-verify
                     boots both.
  tools/             desktop-soak.py (new). desktop-ui-test.py: no-tearing
                     sample moved to the RELOAD button / REPEAT DELAY row since
                     a scale click now magnifies the pixels being sampled.
  docs/              CHANGELOG-1.0.0.md.

  Every app change was made test-first: the failing test was written and run
  (watched fail for the right reason — undeclared symbol or wrong value), then
  the implementation, then green on the target test, the whole apps suite, and
  the freestanding build.


4. THINGS THAT WENT WRONG, AND WHAT THEY CHANGED
------------------------------------------------

  a. Two delegated subagents (calc, task_mgr) hit their iteration cap after
     rate-limit errors and left test_calc.c overwritten with a fragment. The
     original was recovered byte-exact from the session database (read_file
     result, 113 lines) and confirmed by the suite passing. All four apps were
     then finished directly, test-first.

  b. The soak's first run reported an allocator "leak" — frames_used 1451 →
     4656 — that was twelve windows that never closed: the close-box table had
     window ids 2 and 3 assigned to the wrong apps, so the "close" clicks landed
     in content and RAISED windows instead. The harness now fails fast if the
     first three cycles never report one window, and only samples frames_used
     at heartbeats that report exactly one window. The corrected run is the one
     in §2. A test that cannot fail has not passed; this one demonstrably can.

  c. CLAUDE.md says "Highest assigned: 54" for ring-3 roles. It is 66 —
     roles 60–66 exist (65/66 are set via R[k].role, not a `.role =` literal,
     so the grep CLAUDE.md prescribes misses them). This is the exact stale-
     number trap that section documents. The file is protected from agent
     edits; a human should update it. Suggested text is in CHANGELOG-1.0.0.md
     "WHAT THIS RELEASE DOES NOT CLAIM".


5. NOT COVERED (so "verified" stays "measured")
-----------------------------------------------

  - Settings do not persist across boots (by design; the app says so).
  - The soak is one image, one vCPU, 17 cycles, and drives only launch/close.
    It does not minimize, drag, resize, or type. No -smp 4 soak was run
    (desktop-test-smp covers -smp 4 for ~4k frames, not 50k).
  - The no-tearing check samples six frames. It can catch tearing, not prove
    its absence; the claim rests on paired buffers + CPU-0 pinning.
  - One boot per fresh tier, three per dirty tier: cannot see an intermittent
    below ~1 in 10 boots.
  - Nothing on bare metal or Proxmox.
  - desktop-test and the soak ran on the 0.94.0-stringed development desktop
    image (3fde3452…); the 1.0.0 artefact itself passed the same 20 checks
    under release-verify (§2). The two differ only in version strings.
